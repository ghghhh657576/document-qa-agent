后端与系统笔记

一、HTTP 与 HTTPS

1. HTTP 是应用层协议，基于请求-响应模型，无状态；报文分请求行/状态行、
   头部、空行、正文四部分。
2. 常见方法：
   GET 查询（参数放 URL，可缓存、幂等）；
   POST 创建/提交数据（参数放正文，不幂等）；
   PUT 全量更新（幂等）；
   PATCH 局部更新；
   DELETE 删除（幂等）。
3. 常见状态码：
   200 成功；201 已创建；204 无内容；
   301 永久重定向；302/307 临时重定向；
   400 请求参数错误；401 未认证；403 无权限；404 资源不存在；
   405 方法不允许；409 冲突；413 请求体过大；429 请求过多；
   500 服务器内部错误；502 网关错误；503 服务不可用；504 网关超时。
4. HTTPS 在 HTTP 与 TCP 之间加了 TLS 层，解决明文传输、身份伪造、
   数据篡改三件事；握手阶段完成证书校验和密钥协商，之后用对称加密传输。
5. REST 风格把资源放在 URL 上，用方法表达动作；实际接口常混用 RPC 风格，
   团队约定一致即可。
6. 头部要点：
   Content-Type 指定正文格式（application/json、multipart/form-data）；
   Content-Length 正文字节数；
   Authorization 携带令牌；
   Cookie / Set-Cookie 维持会话；
   Cache-Control、ETag、Last-Modified 控制缓存与协商缓存。


二、TCP 与 UDP

1. TCP 面向连接、可靠、按序、有流量控制和拥塞控制，适合网页、文件传输。
2. UDP 无连接、不保证可靠与顺序，开销小、延迟低，适合实时音视频、DNS 查询。
3. 三次握手建立连接：SYN → SYN+ACK → ACK，确认双方收发能力；
   四次挥手释放连接，因为 TCP 全双工，两个方向需要分别关闭。
4. 可靠传输靠序列号、确认应答、超时重传、滑动窗口；拥塞控制包括
   慢启动、拥塞避免、快速重传、快速恢复。
5. 黏包问题：TCP 是字节流没有消息边界，需要应用层定长、分隔符
   或长度前缀来拆包。


三、进程、线程与协程

1. 进程是资源分配的基本单位，有独立地址空间；线程是 CPU 调度的基本单位，
   同一进程内线程共享内存。
2. 线程切换开销小于进程切换，但共享内存需要加锁；进程隔离性好，
   一个进程崩溃通常不影响其他进程。
3. 协程是用户态调度的轻量级并发，切换由程序自己控制，开销远小于线程，
   适合大量 IO 等待的场景。
4. 并发与并行的区别：并发是多个任务交替推进，并行是真正同时执行。
5. 同步阻塞、同步非阻塞、异步回调、协程是常见的 IO 模型；
   高并发服务常用事件循环加非阻塞 IO，避免一个连接占用一个线程。
6. 线程安全：多个线程同时读写共享数据可能产生竞态条件，
   用锁、原子操作、不可变数据或消息队列来避免。


四、数据库与 SQLite

1. 关系型数据库用表、行、列组织数据，靠主键唯一标识一行，
   外键约束保证引用完整性。
2. 索引的本质是额外的有序数据结构（常见 B+ 树），用空间换查询速度；
   在 where、join、order by 涉及的列上建索引收益最大。
3. 索引失效的常见原因：对列做函数运算、隐式类型转换、
   以通配符开头的 like '%x'、不符合最左前缀原则的联合索引。
4. 事务的 ACID：
   原子性（要么全成功要么全回滚）、一致性、隔离性、持久性。
5. 隔离级别从低到高：读未提交、读已提交、可重复读、串行化；
   级别越高并发越差，可能出现的问题有脏读、不可重复读、幻读。
6. SQLite 是单文件嵌入式数据库，零配置、适合本地工具和小型应用；
   写操作会给数据库加锁，同一时刻只有一个写者。
   在 Python 里用 sqlite3 连接时，多线程共享连接要设置 check_same_thread=False，
   并且用一把锁把写操作串行化，否则并发写入可能丢数据或报锁错误。
7. 常用优化：批量插入放在一个事务里、避免 select *、只取需要的列、
   合理使用 limit、对高频查询建索引。
8. 分页查询 offset 很大时性能差，可改用基于上次最大 id 的游标分页。


五、缓存

1. 缓存用空间换时间，把热点数据放在更快的存储里，减少数据库和远程调用压力。
2. 常见缓存位置：进程内字典、本地缓存（LRU）、分布式缓存（Redis/Memcached）、
   HTTP 缓存、数据库查询缓存。
3. 缓存更新策略：
   旁路缓存：先更新数据库再删除缓存（常用），读时未命中再回填；
   写穿/写回：写操作同时更新缓存，或先写缓存异步落库。
4. 缓存穿透：查询不存在的数据导致每次打到数据库，用空值缓存或布隆过滤器。
5. 缓存击穿：热点 key 过期瞬间大量请求涌入，用互斥锁重建或永不/logical 过期。
6. 缓存雪崩：大量 key 同时过期或缓存服务宕机，用过期时间加随机、集群高可用。
7. Redis 常用数据结构：字符串、哈希、列表、集合、有序集合；
   适合做缓存、计数器、排行榜、分布式锁、简单消息队列。
8. 缓存一致性没有完美方案，通常接受最终一致，结合业务容忍度选择策略。


六、Linux 基础

1. 常用命令：ls、cd、pwd、cp、mv、rm、mkdir、find、grep、cat、less、
   tail -f、ps、top、kill、df、du、chmod、chown。
2. 文件权限 rwx 对应读、写、执行，三位一组分别对应所有者、组、其他人；
   数字表示如 755、644。
3. 进程管理：ps aux 查看进程、kill -9 强杀、nohup 加 & 后台运行、
   jobs/fg/bg 管理作业。
4. 日志排查：tail -f 看实时输出、grep 过滤关键字、awk/cut 取列、
   sort | uniq -c 统计频次。
5. 端口与网络：netstat -tlnp 或 ss -tlnp 查看监听端口、curl 测试接口、
   ping 检查连通性、telnet 或 nc 检查端口。
6. 环境变量：export 临时设置，写入 /etc/profile 或 ~/.bashrc 持久化。
7. 磁盘与内存：df -h 看磁盘占用、du -sh 看目录大小、free -h 看内存、
   vmstat 和 iostat 观察系统负载。


七、Docker 基础

1. 镜像（image）是只读模板，容器（container）是镜像运行起来的实例。
2. Dockerfile 常用指令：
   FROM 基础镜像、WORKDIR 工作目录、COPY 复制文件、RUN 构建时执行命令、
   ENV 环境变量、EXPOSE 声明端口、CMD 容器启动命令、ENTRYPOINT 入口。
3. 镜像分层缓存：每条指令生成一层，变化少的指令放前面，构建更快。
4. 数据持久化用 volume 或 bind mount，容器删除数据仍在。
5. 端口映射 -p 宿主端口:容器端口；网络 bridge 模式下容器之间通过网络别名互访。
6. 常用命令：docker build、docker run、docker ps、docker logs、
   docker exec -it、docker stop、docker rm、docker images、docker rmi。
7. 容器里只跑一个主进程，配置和环境变量外置，日志输出到标准输出，
   由外部收集。


八、异步 IO 与服务设计

1. 事件循环不断监听就绪的 IO 事件，把回调或协程恢复执行；
   一个线程可以同时管理成千上万个连接。
2. 异步代码里禁止阻塞调用：time.sleep 换成 asyncio.sleep，
   阻塞型 SDK 放进线程池（asyncio.to_thread）。
3. 常见模式：连接池复用、超时与重试、限流、熔断、优雅关闭。
4. 超时与重试：给每个外部调用设置超时，重试要限制次数并加退避，
   只对幂等操作重试。
5. 限流保护下游：令牌桶、漏桶、固定窗口计数；分布式场景用 Redis 计数。
6. 幂等设计：重复请求不产生副作用，常见做法是唯一请求 id 加去重表、
   数据库唯一索引、状态机校验。
7. 日志分级（DEBUG/INFO/WARN/ERROR），带请求 id 串联调用链，便于排查。
8. 健康检查接口返回服务和依赖状态，供负载均衡与编排系统探测。


九、系统知识常见易错点

1. 时区：数据库存 UTC，展示时再按用户时区转换，避免夏令时和跨时区问题。
2. 时间戳单位：秒和毫秒混用是常见 bug，接口文档要写清单位。
3. 浮点金额用整数分或 Decimal 计算，不要用 float 累加。
4. 编码：统一 UTF-8，读写文件显式指定 encoding。
5. 大文件上传下载要流式处理，不要一次性读进内存。
6. 分页与排序要稳定，否则翻页时可能重复或漏数据。
7. 后台任务与主请求分离，避免接口响应时间被长任务拖慢。
8. 环境区分开发/测试/生产，配置通过环境变量注入，敏感信息不进代码仓库。
