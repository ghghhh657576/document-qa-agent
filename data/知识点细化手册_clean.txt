  用法：不要通读。每次只打开一个阶段，找到当前该学的那一行，照着"搜索关键词"和"验收标准"执行。

〖第 0 部分：学任何知识点前的 30 秒决策〗

· 0.1 先判断该用什么方式学 ·

  内容类型 ｜ 学习方式 ｜ 为什么
  概念/思维（异步、事件循环、为什么需要重排） ｜ 📺 视频，1 个就够 ｜ 动画和口述比文档更容易建立直觉
  API/框架用法（FastAPI、某模型 SDK） ｜ 📄 官方文档 Quickstart ｜ 视频版本常过期；你需要的是"能查"不是"背下来"
  工程结构/最佳实践 ｜ 📦 GitHub 真实项目 ｜ 看别人怎么组织代码，比任何教程都直接
  算法/编程能力 ｜ ⌨️ 只能自己写 ｜ 没有替代品

死规则：每个知识点最多看 1 个视频，看完当天必须写代码。

· 0.2 30 秒判断一个教程值不值得看 ·

打开一个视频/文章后，看这四点，有一条不合格就换：
· 发布时间在 1 年内？（AI 领域超过 1.5 年的基本过期）
· 是动手敲代码，还是念 PPT/念概念？（念 PPT 的只看前 10 分钟）
· 时长是否小于 2 小时？（动辄 40 集的系列课 = 陷阱，会诱导你"看完再动手"）
· 评论区有没有人问"跟着做报错"？（有报错说明作者没维护，换）

· 0.3 搜索技巧（比关键词更重要） ·

· B 站搜法：关键词 + 实战 / 关键词 + 30分钟 / 关键词 + 2025。加"实战"能过滤掉纯理论，加年份能过滤过期内容
· 别搜"XX 教程"，改搜 "XX 从零实现" 或 "XX 踩坑"——后者信息密度高 10 倍
· 报错搜法：直接把报错原文（去掉路径和变量名）粘进搜索框，加上你用的库名
· 问 AI 的模板：
  · "我是 C/C++ 背景，请用指针/线程/状态机类比解释 Python 的 XX"
  · "这段代码逐行解释，重点说清数据是怎么流动的"
  · "我这段代码报错 XXX，帮我定位是哪一行的问题，先别给完整答案"
· 找项目：GitHub 搜 awesome + 关键词（如 awesome-llm-apps），或在 GitHub Trending 看 AI 分类

· 1.2 阶段一的捷径 ·

不要单独写练习代码。 直接开始"AI 伴侣重写"，缺什么学什么：
    第 1~2 周：搭 FastAPI 骨架 + 三张表的模型（学 4、6、8、9）
    第 3~4 周：接上 LLM，实现单轮流式回复（学 1、3、7）
    第 5~6 周：加重试/限流/日志（学 2、5）
    第 7~8 周：Docker 打包 + 推到 GitHub + 写 README（学 10、11）

这样你学的每个东西都立刻有用，记忆牢固，也不会觉得在"为学习而学习"。

· 1.3 卡住时的求助顺序 ·

1. 仔细读报错信息（Python 的报错比 C 友好得多，会告诉你哪一行）
2. 把代码缩到 10 行以内的最小复现
3. 搜报错原文
4. 问 AI，但要求它指出问题所在行而不是直接给完整代码
5. 最后才考虑重看视频（而这通常没用，因为视频教的是正常情况）

· 2.2 阶段二的捷径 ·

    第 1~2 周：用 numpy 手写向量检索（第 3 项）→ 你会真正理解 RAG 为什么有效

"手写一遍"的价值：面试官问"向量检索原理是什么"，答"我用了 Chroma"和答"我用 numpy 实现过余弦相似度检索，知道它的瓶颈是 O(n) 全量扫描，所以生产环境要用 HNSW 索引"——这是两种完全不同的候选人。

· 2.3 手写向量检索的最小代码骨架（给你一个起点） ·

    import numpy as np

    def cosine_similarity(a, b):
        return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

    def search(query_vec, doc_vecs, top_k=3):
        scores = [cosine_similarity(query_vec, v) for v in doc_vecs]
        top_idx = np.argsort(scores)[::-1][:top_k]
        return [(i, scores[i]) for i in top_idx]

练习：把它跑起来之后，自己回答三个问题——① 数据量到 10 万条时慢在哪？② 为什么生产要用专门的向量库？③ 如果两个文档分数很接近，怎么办？

· 3.2 第 6 项"评测体系"具体怎么做 ·

这是最多人忽略、也最容易让你脱颖而出的一项。做法：
1. 收集 30~50 条真实测试问题，人工标注正确答案
2. 写一个脚本，让 Agent 跑完这 50 条，记录：是否答对、用了几步、花了多少 token
3. 用另一个 LLM 当裁判（LLM-as-judge）自动打分
4. 输出一张表：优化前 vs 优化后
简历上写"任务成功率从 58% 提升到 82%，平均步数从 5.1 降到 3.2，单次成本从 ¥0.09 降到 ¥0.04"——这一行比"精通 LangChain"有力 100 倍。

· 3.3 阶段三的捷径 ·

不要按顺序学 1→10。 正确顺序是：
    先做主力项目（第 1、2、3 项边做边学）
    → 项目能跑了，加评测（第 6 项）
    → 加 trace（第 7 项）
    → 加安全（第 8 项）
    → 最后才看 LangGraph（第 5 项）和 MCP（第 4 项）

因为框架是最后学的，不是最先学的。先有需求再学工具，你才知道框架在解决什么问题；反过来先学框架，你只会照着示例抄。

· 4.1 先补 Python 工具库（1~2 周，8 小时） ·

  deque ｜ BFS 队列，O(1) 出队 ｜ python deque 用法

· 4.3 一个必须遵守的规则 ·

每刷完一个专题，合上答案从头重写一遍。 看着答案写出来的代码不算会。这是唯一有效的复习方式——看第二遍题解是自欺欺人。

· 4.4 ⭐ Python 算法怎么练（完整的练习方法） ·

  你现在的核心矛盾：算法思维有了（C 语言练出来的），Python 的表达速度跟不上。
  所以练法不是"重新学算法"，而是把已有思维翻译成 Python。

· 4.4.1 每道题的六步练习法（严格执行，不要跳步） ·

  步骤 ｜ 做什么 ｜ 时间 ｜ 为什么
  ① 独立思考 ｜ 自己想，哪怕想不出来 ｜ 15 min ｜ 直接看答案 = 没练到"从零构造解法"的能力
  ② 只看思路 ｜ 看题解但只看思路，不看代码 ｜ 5 min ｜ 看代码会跳过"翻译成代码"这个关键环节
  ③ 合上重写 ｜ 关掉题解，自己写出来 ｜ 15 min ｜ 这一步才是真正的练习
  ④ 三问自检 ｜ 复杂度？边界？有没有更 Python 的写法？ ｜ 5 min ｜ 见下面
  ⑤ 三天后重写 ｜ 不看任何资料再做一遍 ｜ 10 min ｜ 对抗遗忘的唯一有效手段（见 7.6）
  ⑥ 记录 ｜ 记到 刷题记录.tsv ｜ 1 min ｜ 知道自己的薄弱专题在哪

第 ④ 步的三个自检问题（很多人跳过这步，导致刷了 200 题还是不会）：
1. 时间复杂度是多少？怎么算出来的？（面试必须能当场说）
2. 边界情况处理了吗？（空数组、单元素、极值、重复元素）
3. Python 里有没有更简洁的写法？（切片 / 推导式 / Counter / deque）

· 4.4.2 "一题两写"训练法（专门为你设计） ·

你有 C 语言基础，这是优势而不是包袱。用法：
    每道题写两遍：
      第一遍：用 C 写（快，你有肌肉记忆，确认算法思路是对的）
      第二遍：用 Python 写（慢，但你在建立新的肌肉记忆）

坚持 20 天（每天一题），Python 写题的速度会追上来。原因是：
· 你的算法思维不需要重新学（C 那遍已经验证了）
· 你需要练的只是"这个操作在 Python 里怎么写"
· 对比两遍的差异，你会快速建立映射（比如 C 手写队列 → Python 的 deque）
20 天之后停掉 C 那遍，全部用 Python。这时候你已经完成迁移了。

· 4.4.3 配套工具：算法训练.py ·

本目录下有一个可以用的训练工具：
    python 算法训练.py syntax     # Python 算法题必备语法速查（10 类高频语法）
    python 算法训练.py compare    # C 和 Python 的写法对比（5 个典型例子）
    python 算法训练.py quiz       # 随机抽一道模板题，附练习流程提示
    python 算法训练.py log        # 记录今天刷的题（日期/题号/状态/专题/笔记）
    python 算法训练.py stats      # 看统计：掌握程度、各专题题量、待复习清单

特别推荐 quiz 命令：它按专题抽题（内置 60+ 道模板题，覆盖数组/滑窗/链表/二叉树/回溯/DP/二分/栈/堆/图），抽完直接给你六步练习流程。
stats 的价值：它会算出你的"独立做出比例"。投递前这个数字应该 ≥ 70%；如果低于 50%，说明你在"看题解刷题"，那是无效练习。

· 4.4.4 记模板，不记题 ·

刷题的目标不是"记住 250 道题"，而是建立模板识别能力：
  ❌ 无效 ｜ ✅ 有效
  按题号顺序刷 ｜ 按专题刷，一个专题吃透再进下一个
  记住每道题的解法 ｜ 记住 15~20 个模板
  反复看题解 ｜ 每个专题结束合上答案重写
  追求刷题总量 ｜ 追求"看到新题能归类到模板"

为什么按专题刷：同一专题的题共享解题模式，集中刷才能形成"模式识别"。跳着刷的话，每道题对你都是新题。

· 4.4.5 面试前 2 周怎么复习 ·

不要随机刷题，按专题限时检索：
    今天：只做二叉树的题，限时 20 分钟一道，白板/纸上写（不开编辑器自动补全）
    明天：只做 DP 的题
    后天：只做链表 + 双指针

限时 + 手写（不用 IDE 的补全）是最接近真实面试的练习方式。用编辑器刷题会让你在面试时手生。

· 4.5 加分项（学有余力时） ·

从零实现一个简易向量索引（暴力检索 → KD-Tree 或 HNSW 的原理版）。这一个项目同时展示算法能力和 AI 理解，面试时是非常好的话题，而且能把你的两个身份（算法训练 + AI 方向）连起来。

〖第 5 部分：明确不要学的东西〗

10 小时/周的时间预算下，下面这些现在碰都不要碰。它们不是没用，而是对你的当前目标（拿到实习）性价比太低：
  不学的东西 ｜ 为什么现在不学
  HNSW / IVF 的数学细节 ｜ 知道"有这么个索引、为什么快"就够了，实现细节面试不会深挖

  vLLM 推理部署 ｜ 通常是平台/基础设施团队的事
  多 Agent 协作框架 ｜ 90% 的场景是过度设计，面试官更想看你会不会判断"什么时候不该用"
  多模态（图像/视频） ｜ 除非你的项目非用不可
  Transformer 数学推导 ｜ 到"直觉层"就停，推导是算法岗的要求
  同时学 3 个 Agent 框架 ｜ 深度 > 广度。会 1 个 + 理解原理 > 会 5 个都只会抄示例

· 7.4 ⭐ 整合规则（回答"零碎知识怎么串起来"） ·

核心答案：不需要刻意整合。用同一个项目当主线，知识点自然就串起来了。

· 规则一：项目是主线，知识点是珠子 ·

    ❌ 错误模型：学完 A → 学完 B → 学完 C → 再想怎么用
    ✅ 正确模型：定下项目 → 需要 A 就学 A 并接进去 → 需要 B 就学 B 并接进去

· 规则二：检验整合的唯一标准 ·

  每学一个知识点，问自己："它出现在我项目的哪个文件里？"
  找不到对应文件 → 这个知识点还没整合，等于没学。

· 规则三：整个规划只产出 3 个东西，不是 50 个知识点 ·

  产物 ｜ 时间 ｜ 作用
  ① AI 伴侣重写版 ｜ 2027 年 5 月 ｜ 证明你会工程化 Python + 懂 LLM 应用
  ② 主力 Agent 项目 ｜ 2027 年 8 月 ｜ 简历主角，面试被追问 40 分钟
  ③ 一段实习经历 ｜ 2027 年底 ｜ 让你够到大厂暑期实习的门槛

其余 50 个知识点都是为这 3 个产物服务的。 不服务它们，就没有优先级。

· 规则四：接进项目的顺序（这就是整合地图） ·

  时间 ｜ 学到什么 ｜ 项目因此多了什么能力
  2026.10~12 ｜ Python 语法、异常、logging、Git ｜ 代码能看懂、能整理了
  2027.1~2 ｜ 异步、装饰器、FastAPI、SQLAlchemy ｜ 能同时处理多个用户
  2027.3~4 ｜ 生成器、流式输出、SSE ｜ 用户不用干等 5 秒
  2027.4 ｜ Embedding、余弦相似度、手写检索 ｜ AI 能记住长期信息
  2027.5 ｜ 切分策略、pgvector、RAG 全链路 ｜ 记忆能存几万条
  2027.5 ｜ 限流、重试、缓存、Redis ｜ API 挂了不会崩
  2027.6 ｜ 评测、日志、pytest ｜ 有了准确率数字
  2027.6 ｜ Docker、Linux、云服务器部署 ｜ 有一个能点开的链接

每一行都是"学一个东西 → 项目多一个能力"。这就是整合。 你不需要在学完之后再想办法串联，因为从第一天起它们就在同一根线上。

· 7.5 学不进去时的自我检查 ·

某个知识点学了两周还没接进项目，问自己：
1. 我是不是在写"练习代码"而不是"项目代码"？（练习代码学完就忘）
2. 这个知识点我现在真的需要吗？（不需要就跳过，标记"以后再说"）
3. 我是不是在追求"彻底理解"？（工程上 80% 够用就行，剩下 20% 遇到问题再补）

· 7.6 ⭐ 遗忘问题怎么解决 ·

  先说结论：遗忘是正常现象，不是记性差。
  而且——工程师的核心能力不是"记住"，而是"知道有这个东西 + 能快速查回来 + 上手就用"。没有任何一个在职工程师是靠背下来工作的。

· 7.6.1 第一步：把知识点分成三类（这是最重要的一步） ·

你感觉"遗忘严重"，很大一部分原因是你在用同一种方式对待三种完全不同的知识。
  类别 ｜ 包括什么 ｜ 正确策略 ｜ 判断标准
  A 类：必须形成肌肉记忆 ｜ Python 基础语法、异步写法、git 常用命令、调试流程 ｜ 靠反复使用，不靠背。写够次数自然就记住了 ｜ 面试要白板写代码，没时间查
  B 类：需要记住"有这个东西" ｜ 各种库/工具的存在与用途、设计模式名称、架构模式 ｜ 只记索引，不记内容。知道"有个东西叫语义缓存能省钱"就够了，用的时候查文档 ｜ 面试会问"你知道怎么解决 X 吗"
  C 类：面试八股，必须精确记住 ｜ GIL 是什么、进程线程协程区别、HTTP 状态码、索引原理、RAG 流程 ｜ 需要真正的记忆，用间隔重复（见 7.6.3） ｜ 面试要当场答，答错直接扣分

绝大多数人的错误：把 B 类当成 C 类去背（浪费大量时间），或者把 C 类当成 B 类不去记（面试被问倒）。
关键认知：编程知识的 90% 属于 A 类和 B 类，不需要"记住"，只需要"用过"。 你真正需要背的只有 C 类，而 C 类的量比你想的少得多——大概 30~50 个问题。

· 7.6.2 第二步：判断你"遗忘"的真实原因（对症下药） ·

  症状 ｜ 真实原因 ｜ 药方
  "学过的东西过两周就想不起来了" ｜ 学完就没再用过——这是最主要的原因，占 80% ｜ 把它接进项目（见 7.4 整合规则）。用过的知识不会忘
  "当时看懂了，现在完全想不起来在讲什么" ｜ 当时是"看懂了"而不是"会用了"——被动输入不产生记忆 ｜ 回到 7.4 规则二：合上资料从空文件重写一遍
  "记得概念，但写不出代码" ｜ 正常。概念和技能是两种记忆 ｜ 概念用间隔重复（C 类），技能靠动手次数（A 类）
  "面试题背了又忘" ｜ 你在死记答案，没理解原理 ｜ 用"为什么"代替"是什么"来记（见 7.6.4）

最重要的一句：如果你对某个知识点没有"用过"的记忆，忘记它是必然的，而且不应该靠复习来补救——应该靠使用来补救。

· 7.6.3 第三步：C 类知识用间隔重复（唯一需要"复习"的部分） ·

工具：Anki（免费，电脑手机都有）。搜索关键词：anki 入门 / anki 计算机 面试 卡片。
做法：
1. 只给 C 类（面试八股）做卡片。A 类和 B 类不要做卡片，那是浪费时间
2. 卡片数量控制在 50~150 张，不要贪多
3. 每天花 5~10 分钟复习，不要额外挤占你的 10 小时预算
4. 到面试前 1 个月，把复习量提到 15 分钟
制卡的四条铁律（违反任何一条，卡片就无效）：
· ❌ 不要整段抄书。一张卡只放一个知识点
· ❌ 不要做"选择题式"卡片。必须能主动回忆，不能只是"看着眼熟"
· ✅ 卡背要写"为什么"，不只是"是什么"。例：
  · 正面：为什么 Python 的异步不能加速 CPU 密集任务？
  · 背面：因为异步只在 IO 等待时切换（不阻塞事件循环），而 CPU 计算期间无法切换；且 GIL 限制了多线程并行。所以 CPU 密集要用多进程。
· ✅ 用自己的话写，不要复制原文（复制的东西大脑不编码）

· 7.6.4 第四步：把"记忆"变成"检索练习"（比复习有效 3 倍） ·

认知科学里最可靠的结论之一：主动回忆（retrieval）的效果远大于被动复习（review）。
具体到你的场景：
  ❌ 无效（被动复习） ｜ ✅ 有效（主动检索）
  重看视频 / 重读笔记 ｜ 合上资料，从空白文件写一遍
  划重点、抄笔记 ｜ 白板讲一遍（对着空气讲，或讲给同学）
  看第二遍题解 ｜ 不看答案重写代码
  读 RAG 流程图 ｜ 在白纸上默画 RAG 架构，然后对照补漏

一个立刻能用的方法：每周花 15 分钟，拿一张白纸，尝试写出本周学的所有东西——写不出来就是没记住，写出来的部分就是真正属于你的。

· 7.6.5 第五步：算法遗忘怎么办（这是你最容易焦虑的部分） ·

刷了 250 题，两个月后忘了 200 题——这完全正常，而且不需要"全部记住"。
正确做法是记模板，不记题：
  不要这样做 ｜ 要这样做
  记住每道题的解法 ｜ 记住 15~20 个模板：滑动窗口、双指针、二分、DFS/BFS、回溯、DP 的几种基本型
  按题号顺序刷 ｜ 按专题刷，每个专题吃透后再进下一个
  反复看题解 ｜ 每个专题结束后，合上答案重写一遍
  追求刷题总量 ｜ 追求"看到新题能归类到模板"

面试前的正确复习方式：不要随机刷题，按专题限时检索——比如今天只做二叉树的题，限时 20 分钟一道。这是最接近面试的练习方式。

· 7.6.6 一张表：什么该记，什么不该记 ·

  该记（C 类） ｜ 不该记（B 类，查就行）
  GIL、进程/线程/协程区别 ｜ FastAPI 的具体装饰器写法
  HTTP 状态码、GET/POST 区别 ｜ 某个库的函数名和参数
  SSE 与 WebSocket 区别 ｜ Dockerfile 的指令细节
  数据库索引原理、事务隔离级别 ｜ SQLAlchemy 的 API
  RAG 完整流程、召回优化手段 ｜ LangGraph 的节点配置
  Function Calling 的原理 ｜ 各家模型 API 的字段名
  Agent 死循环的原因与解法 ｜ 某个框架的版本差异

记忆口诀：
  原理要记，API 不记；方案要记，语法不记；为什么记，怎么写不记。

· 7.6.7 最重要的那句 ·

  你不是记性差，你只是还没"用够"。
  写 100 次 async def 之后，你不需要背它；在项目里查 20 次文档之后，那些 API 自然就记住了。
  忘记的知识点，最好的补救不是复习，而是用它做点东西。

〖第 7.7 节：C 语言背景的 Python 迁移指南 ⭐〗

  适用症状："C 里的指针、链表这些，在 Python 里根本无从下手。"
  这个困惑是对的，不是你的问题。原因很简单：Python 里指针这个概念消失了，链表也被内置类型接管了。 你不是不会，而是没有东西可写。

· 7.7.1 指针：不是"换了写法"，而是"根本不用写" ·

  C 语言 ｜ Python ｜ 说明
  struct Node { int val; Node *next; } ｜ class Node: ｜ 语法不同，概念一样
  Node *p ｜ p ｜ 变量本身就是引用，不用写 *
  p->next ｜ p.next ｜ -> 变成 .（Python 没有箭头）
  NULL ｜ None ｜ 空指针就是 None
  malloc(sizeof(Node)) ｜ Node(1) ｜ 构造对象，不用手动分配
  free(p) ｜ 不用写 ｜ 垃圾回收自动处理
  &x（取地址） ｜ 不用写 ｜ Python 变量天生是引用
  *p（解引用） ｜ 不用写 ｜ Python 自动解引用

关键认知：Python 里"指针"变成了语言的默认行为。 你在 C 里写 *、->、& 的地方，Python 什么都不用写。
这在 C 里是个重要概念（要学一学期），在 Python 里是语言的隐含前提。所以"无从下手"的真实原因是：没有等价的代码可写。

· 7.7.2 链表：Python 里几乎不用自己写 ·

C 里用手写链表的四大场景，Python 都有内置替代品：
  你想解决的问题 ｜ C 的做法 ｜ Python 的做法 ｜ 复杂度
  动态数组 ｜ 链表 或 手动 realloc ｜ list ｜ 追加 O(1)
  队列（先进先出） ｜ 链表（出队 O(1)） ｜ collections.deque ｜ 两端 O(1)
  栈 ｜ 链表 ｜ list（append/pop） ｜ O(1)
  哈希表（含冲突处理） ｜ 数组 + 链表 ｜ dict / set ｜ O(1) 均摊
  LRU 缓存淘汰 ｜ 哈希表 + 双向链表 ｜ OrderedDict，或自己实现 ｜ ← 只有这个真需要手写

结论：C 数据结构课里的链表、队列、栈、哈希表，在 Python 里 4/5 有内置实现，你不需要把 C 的练习在 Python 里重做一遍。

· 7.7.3 但链表仍然要练——只是练法和目的不同 ·

目的不是"学会链表"（你已经在 C 里学会了），而是三件事：
1. 熟悉 Python 的类、引用语义、None 判断
2. 在 LeetCode 里能流畅操作以 ListNode 形式给出的链表（这是笔试常见题型）
3. 理解引用类型的行为——这是 Python 里最容易出错的地方
对照示例（反转链表，可以逐行对照）：
    // C 语言
    Node *prev = NULL, *cur = head;
    while (cur != NULL) {
        Node *nxt = cur->next;
        cur->next = prev;
        prev = cur;
        cur = nxt;
    }
    return prev;

    # Python —— 逻辑完全一样，只是少了 * 和 ->
    def reverse_list(head: Optional[ListNode]) -> Optional[ListNode]:
        prev = None                      # NULL → None
        cur = head                       # 不需要声明类型
        while cur is not None:           # != NULL → is not None
            nxt = cur.next               # -> 变 .
            cur.next = prev
            prev = cur
            cur = nxt
        return prev

看到没有——逻辑一模一样。 你不需要"重新学链表"，只需要把 NULL 换成 None、-> 换成 .。

· 7.7.4 Python 特有的坑（C 程序员最容易错的地方） ·

  坑 ｜ 表现 ｜ 原因
  == vs is ｜ 判断两个节点是否是同一个对象，要用 is，不是 == ｜ == 比较值，is 比较身份（相当于 C 的指针地址比较）
  可变对象的共享引用 ｜ a = b 后改 b，a 也变了 ｜ 两者指向同一个对象（类似 C 里两个指针指向同一块内存）
  默认参数是可变对象 ｜ def f(x, lst=[]) 会跨调用累积 ｜ 默认值只在定义时创建一次
  浅拷贝 vs 深拷贝 ｜ list(a) 只复制一层 ｜ 嵌套对象仍共享引用

特别提醒第一条：is 就是 C 的指针比较。has_cycle 里判断快慢指针相遇必须用 is。

· 7.7.5 最值得练的一道题：LRU 缓存 ·

为什么是它：同时用到"哈希表 + 双向链表"（你 C 数据结构课的核心内容），而且是真实工程里真会用到的东西（缓存淘汰、连接池）。
· 参考实现：链表对照.py（本目录下，可直接运行）
· 练习顺序：先跑一遍看输出 → 删掉 LRUCache 类 → 自己从零重写
验收标准：你的代码里如果出现 *、->、malloc、free，说明你在翻译 C 而不是在写 Python。

· 7.7.6 正确的心态 ·

  你的 C 语言能力不是包袱，是资产。
  理解指针的人，理解 Python 的引用语义会比别人快得多——因为你知道"变量指向对象"是什么意思。
  你要做的不是"忘掉 C 重学 Python"，而是把 C 的思维翻译成 Python 的表达。翻译的关键是：先想清"要做什么操作"，再问"Python 里这操作怎么写"，而不是逐行对照 C 代码。
